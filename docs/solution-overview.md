# Solution Overview — EduGuard AI

## Core Mechanism

EduGuard AI is a **multi-factor AI risk scoring platform** built on IBM Bob that continuously monitors student academic and behavioural signals, computes a dropout risk score for each student, and generates personalised intervention plans that coordinators can act on immediately.

The system works in three phases:

### Phase 1 — Data Ingestion
- Academic data: Attendance %, internal marks, assignment submission rate, lab attendance, class participation
- Behavioural data: Financial stress index (0–10), social/personal issues index (0–10), active backlogs
- Trend signals: Semester-over-semester performance direction (improving / stable / declining)
- Data enters via: CSV import from university ERP, manual form entry, or future API integration with CHARUSAT's FMIS

### Phase 2 — Risk Computation (IBM Bob Agent Mode)
IBM Bob's Agent Mode runs a weighted multi-factor scoring model:

```
Risk Score =
  (100 - Attendance)    × 0.28  +   ← Most critical academic signal
  (100 - Marks)         × 0.25  +
  (100 - Assignments)   × 0.15  +
  (100 - Lab)           × 0.10  +
  (100 - Participation) × 0.10  +
  Financial Stress      × 1.0   +   ← Behavioural signals
  Social Issues         × 0.5   +
  Backlogs              × 1.8       ← Capped at 12 pts
  + Trend Modifier (±4 pts)
```

Risk levels: **High (66–100)**, **Medium (36–65)**, **Low (0–35)**
Dropout probability estimated via sigmoid-like function calibrated to AICTE dropout data.

### Phase 3 — Intervention Generation (IBM Bob Plan Mode)
For each at-risk student, IBM Bob uses **Plan Mode** to design an optimal multi-stakeholder intervention sequence:
- Maps each risk factor to the appropriate support resource (faculty, counsellor, welfare cell)
- Assigns CRITICAL / HIGH / MEDIUM / LOW priority to each action
- Specifies responsible party and timeline for each action
- Respects institutional hierarchy and available support mechanisms at CHARUSAT

## What Makes It Different from Naive Alternatives

| Approach | Limitation | EduGuard's Advantage |
|----------|-----------|----------------------|
| Single-metric alert (attendance only) | Misses financially stressed students who still attend | 8-factor model captures the full picture |
| Generic counselling referral | Treats all students the same | Personalised plan per student based on their specific risk profile |
| End-of-semester review | Always too late | Real-time, continuous monitoring throughout the semester |
| Manual coordinator intuition | Biased, inconsistent, not scalable | Objective, data-driven, works for 500+ students simultaneously |
| Raw ERP dashboards | Data without insight | AI-generated risk score + prioritised action plan |

## Key Design Decisions

1. **No backend required** — works as a static web app with CSV import. This means zero IT setup, works offline, deployable in 5 minutes. IBM Bob handles the AI layer.

2. **IBM Bob is load-bearing, not decorative** — Bob's Agent Mode drives the risk computation logic, Plan Mode generates interventions, and the chat interface lets coordinators query student data conversationally. Removing Bob would break the core functionality.

3. **CSV import first** — Rather than requiring API integration with CHARUSAT's ERP (which takes months), coordinators can export their existing attendance/marks data to CSV and import it instantly. Pragmatic path to adoption.

4. **Transparency over black box** — Every risk score shows the top contributing factors with exact values. Coordinators can see *why* a student is flagged, not just *that* they are flagged.

5. **Intervention plans are actionable, not generic** — Each plan specifies the exact action, the responsible person (by role), and a realistic timeline. No vague "monitor the student" recommendations.

## User Experience

1. Coordinator opens EduGuard AI dashboard → sees instant overview: 8 high-risk, 10 medium-risk students
2. Clicks a student card → animated risk gauge shows 78/100, top 3 risk factors highlighted, 5-step intervention plan generated by Bob
3. Coordinator asks IBM Bob chat: *"Who needs urgent attention this week?"* → Bob responds with prioritised list + recommended actions
4. Coordinator exports intervention report as CSV, shares with Student Welfare Cell
5. Imports updated attendance data next week → risk scores automatically recomputed
